Introduction

Contexte

Les indicateurs socio-économiques constituent un levier essentiel pour la compréhension du développement territorial et la prise de décision stratégique. Axiora Data a été développé comme une plateforme intelligente d’analyse, de visualisation et de prévision des indicateurs socio-économiques régionaux basés sur les données du HCP.

Problématique

Les données publiques sont souvent statiques (PDF, tableaux bruts), ce qui limite l’exploration interactive, la comparaison multi-années et la projection des tendances futures. Il existe donc un besoin d’un outil interactif, dynamique, prédictif et orienté aide à la décision.

Vision

Axiora Data est une plateforme d’intelligence socio-économique combinant Data Analytics, Visualisation avancée, Intelligence artificielle, Géospatial et automatisation de reporting.

Aperçu de la plateforme

Objectifs

  • Centraliser et structurer les indicateurs socio-économiques (HCP) pour la région Souss-Massa.
  • Permettre une exploration interactive (années, provinces, communes, indicateurs).
  • Faciliter la comparaison multi-années et multi-territoires (variation %, tendances).
  • Intégrer un module de prévision (ML) pour projeter l’évolution des indicateurs.
  • Renforcer l’aide à la décision via un assistant IA et des rapports automatiques.

Fonctionnalités clés

  • Dashboard : indicateurs synthétiques et vues rapides.
  • Exploration des indices : Population, Travail, Habitat, Finance, Enseignement, Pauvreté.
  • Filtres dynamiques : année, province/commune, type d’indicateur, mode comparaison.
  • Visualisations interactives : courbes, barres, heatmaps, scatter, tableaux.
  • Cartes géographiques : choroplèthes pauvreté/vulnérabilité avec tooltips & zoom.
  • Prévisions ML : projection de tendances et visualisation des prédictions.
  • Assistant IA : réponses, résumés et interprétation des résultats.
  • Rapports PDF : génération automatique avec graphiques + cartes + synthèse.

Données & Préparation (Cleaning)

Dans AXIORA, l’objectif est de conserver les données brutes telles qu’elles sont (traçabilité), puis de produire une version finale propre (numérique, cohérente) exploitable par les modules: analytics, cartographie, IA Q&A et générateur de rapports.

1) Sources de données (brutes)

  • RGPH / Structure démographique (Excel): RGPH2014.xlsx
  • Pauvreté / Indicateurs (Excel): chtouka pauvr.xlsx

Organisation recommandée (dans ton repo): 

axiora/
  post/

    RGPH2014.xlsx
    chtouka pauvr.xlsx
    outputs/
      (fichiers générés automatiquement)

2) Principe AXIORA: « brut » vs « final »

✅ Données brutes

On ne les “corrige” pas: on les garde comme preuve (format d’origine, séparateurs, pourcentages, champs vides). Elles servent aussi à reproduire le cleaning à tout moment.

✅ Données finales (clean)

Version normalisée et numérique: colonnes renommées, types convertis, valeurs manquantes gérées, et export en CSV/Parquet/JSON pour le dashboard, la carte, et l’IA.

3) Pipeline de cleaning (étapes + code)

Le pipeline ci-dessous est écrit pour Python + Pandas. Il s’exécute localement (ou notebook), lit les fichiers Excel bruts, produit une table propre, puis génère un JSON “dic complet” (structure prête à être consommée par AXIORA). 

# ✅ Installation (si besoin)
# pip install pandas openpyxl pyarrow

from pathlib import Path
import re
import json
import pandas as pd

BASE_DIR = Path(__file__).resolve().parent  # dossier: axiora/post/
RGPH_PATH = BASE_DIR / "RGPH2014.xlsx"
PAUV_PATH = BASE_DIR / "chtouka pauvr.xlsx"

OUT_DIR = BASE_DIR / "outputs"
OUT_DIR.mkdir(exist_ok=True)

Étape A — Lecture des fichiers (sans altérer le brut)

On charge l’Excel en gardant les valeurs telles qu’elles apparaissent (espaces, “%”, séparateurs). Ensuite seulement on crée une copie “work” pour transformer. 

# 1) Lire RGPH (choisis sheet_name si ton fichier a plusieurs feuilles)
rgph_raw = pd.read_excel(RGPH_PATH, sheet_name=0, dtype=str)  # tout en texte = brut
rgph = rgph_raw.copy()  # version de travail

# 2) Lire pauvreté (si utilisé dans une jointure plus tard)
pauv_raw = pd.read_excel(PAUV_PATH, sheet_name=0, dtype=str)
pauv = pauv_raw.copy()

print("RGPH brut:", rgph_raw.shape, " | Pauv brut:", pauv_raw.shape)

Étape B — Standardiser les noms de colonnes

Les fichiers RGPH contiennent souvent des colonnes avec espaces multiples, accents, et variantes (Supereficie Km², Population légale, etc.). On normalise pour avoir des clés stables. 

def norm_col(c: str) -> str:
    c = (c or "").strip()
    c = re.sub(r"\s+", " ", c)              # espaces multiples -> 1 espace
    c = c.replace("²", "2")                # Km² -> Km2
    c = c.replace("%", "pct")              # % -> pct
    c = c.replace("-", "_")
    c = c.replace("’", "'")
    c = c.lower()
    c = re.sub(r"[^a-z0-9_ ]", "", c)      # retirer caractères spéciaux
    c = c.replace(" ", "_")
    return c

rgph.columns = [norm_col(c) for c in rgph.columns]
pauv.columns = [norm_col(c) for c in pauv.columns]

print(rgph.columns.tolist())

Étape C — Nettoyer les chiffres (espaces, séparateurs, %)

Dans tes données, on voit des nombres comme 33 848 242 (espaces fines) et des pourcentages comme 49,8% ou des décimaux 10,2. L’objectif est de convertir tout ça en numérique fiable. 

NBSP = "\u00A0"     # non-breaking space
NNBSP = "\u202F"    # narrow no-break space (souvent utilisé comme séparateur)

def to_number(x):
    """Convertit '33 848 242', '49,8%', '10,2' -> float/int. Retourne NA si vide."""
    if x is None:
        return pd.NA
    s = str(x).strip()
    if s == "" or s.lower() in {"na", "n/a", "nan", "none"}:
        return pd.NA
    # retirer % et espaces spéciales
    s = s.replace("%", "")
    s = s.replace(NNBSP, "").replace(NBSP, "").replace(" ", "")
    # décimales FR
    s = s.replace(",", ".")
    # garder seulement chiffres + point + signe
    s = re.sub(r"[^0-9\.\-+]", "", s)
    if s in {"", ".", "-", "+"}:
        return pd.NA
    try:
        val = float(s)
        # si entier exact, retourner int (optionnel)
        if val.is_integer():
            return int(val)
        return val
    except ValueError:
        return pd.NA

Ensuite, on applique la conversion aux colonnes numériques RGPH (surface, populations, parts, âges). Les colonnes qui restent en texte: localites (nom), et parfois un code administratif (conc). 

# Exemple: adapter si tes colonnes ont d'autres noms après normalisation
text_cols = {"conc", "localites"}  # à garder en texte
num_cols = [c for c in rgph.columns if c not in text_cols]

for c in num_cols:
    rgph[c] = rgph[c].map(to_number)

# Harmoniser "conc" si vide (certaines lignes ont le code dans une autre colonne ou vide)
if "conc" in rgph.columns:
    rgph["conc"] = rgph["conc"].astype("string").str.strip()

Étape D — Gérer les lignes “structure” et les valeurs manquantes

Dans ton extrait, certaines lignes sont des sous-niveaux (ex: Drargua Rural) sans chiffres. On ne supprime pas aveuglément: on les marque (is_empty_row) et on décide selon le besoin: exclure pour l’analyse, ou garder pour l’arborescence administrative. 

def row_is_empty_numeric(df: pd.DataFrame, numeric_columns: list[str]) -> pd.Series:
    # vrai si toutes les colonnes numériques sont vides/NA
    return df[numeric_columns].isna().all(axis=1)

numeric_columns = [c for c in rgph.columns if c not in {"conc", "localites"}]
rgph["is_empty_row"] = row_is_empty_numeric(rgph, numeric_columns)

# Nettoyer nom localité
if "localites" in rgph.columns:
    rgph["localites"] = rgph["localites"].astype("string").str.strip()

# Dataset "analysis_ready" (uniquement lignes avec valeurs)
rgph_analysis = rgph.loc[~rgph["is_empty_row"]].copy()

Étape E — Contrôles qualité (cohérence rapide)

On ajoute des checks simples pour détecter anomalies fréquentes: parts homme/femme ≈ 100%, groupes d’âge ≈ 100% (si exprimés en %), et pop municipale ≤ pop légale (souvent proche). 

def approx_sum(df, cols, tol=2.0):
    s = df[cols].sum(axis=1, skipna=False)
    return (s.between(100 - tol, 100 + tol)) | s.isna()

# Adapter aux noms exacts après normalisation
sex_cols = [c for c in rgph_analysis.columns if c in {"part_mas", "part_fem"}]
if len(sex_cols) == 2:
    rgph_analysis["qc_sex_100"] = approx_sum(rgph_analysis, sex_cols, tol=2.0)

# Ex: colonnes d'âge: 0_4_ans, 5_9_ans, ...
age_cols = [c for c in rgph_analysis.columns if re.match(r"^\d+_\d+_ans$", c) or c in {"m15ans", "15_59_ans", "60ans_et_plus"}]
if len(age_cols) >= 5:
    rgph_analysis["qc_age_100"] = approx_sum(rgph_analysis, age_cols, tol=6.0)

# Pop check (si colonnes présentes)
if {"population_legale", "population_municipale"}.issubset(rgph_analysis.columns):
    rgph_analysis["qc_pop_ok"] = rgph_analysis["population_municipale"] <= rgph_analysis["population_legale"]

Étape F — Export “final” (CSV/Parquet/JSON)

On exporte la version propre. Parquet est idéal pour performance (dashboard), CSV pour compatibilité, JSON pour l’API et le front. 

rgph_analysis.to_parquet(OUT_DIR / "rgph_clean.parquet", index=False)
rgph_analysis.to_csv(OUT_DIR / "rgph_clean.csv", index=False, encoding="utf-8")

# JSON records (liste de lignes)
rgph_analysis.to_json(OUT_DIR / "rgph_clean.json", orient="records", force_ascii=False)

Étape G — Données finales sous forme de “dic complet” (structure AXIORA)

Ici, on construit un dictionnaire complet par localité: métadonnées + indicateurs + distribution d’âge. C’est le format pratique pour: IA Q&A (“répondre aux questions”), cartes, et rapports PDF. 

def build_axiora_dict(df: pd.DataFrame) -> dict:
    out = {}

    # Colonnes attendues (adapter si besoin)
    key_code = "conc" if "conc" in df.columns else None
    key_name = "localites" if "localites" in df.columns else None

    for _, row in df.iterrows():
        code = str(row[key_code]) if key_code else None
        name = str(row[key_name]) if key_name else None
        # clé unique: code si présent, sinon nom
        k = code if code and code != "<NA>" else name

        # Exemple de blocs
        meta = {
            "code": code,
            "name": name,
        }

        demo = {}
        for c in ["supereficie_km2", "population_legale", "population_municipale"]:
            if c in df.columns:
                demo[c] = row[c] if pd.notna(row[c]) else None

        sex = {}
        for c in ["part_mas", "part_fem"]:
            if c in df.columns:
                sex[c] = row[c] if pd.notna(row[c]) else None

        age = {}
        # colonnes âge typiques: 0_4_ans, 5_9_ans, 10_14_ans + m15ans + 15_59_ans + 60ans_et_plus
        for c in df.columns:
            if c in {"m15ans", "15_59_ans", "60ans_et_plus"} or re.match(r"^\d+_\d+_ans$", c):
                age[c] = row[c] if pd.notna(row[c]) else None

        qc = {}
        for c in ["qc_sex_100", "qc_age_100", "qc_pop_ok"]:
            if c in df.columns:
                qc[c] = bool(row[c]) if pd.notna(row[c]) else None

        out[k] = {
            "meta": meta,
            "demography": demo,
            "sex_structure": sex,
            "age_structure": age,
            "quality_checks": qc
        }

    return out

rgph_dict = build_axiora_dict(rgph_analysis)

with open(OUT_DIR / "rgph_dict.json", "w", encoding="utf-8") as f:
    json.dump(rgph_dict, f, ensure_ascii=False, indent=2)

print("✅ Dictionnaire généré:", OUT_DIR / "rgph_dict.json")

Résultat: outputs/rgph_dict.json contient une entrée par localité (clé = code si présent).

5) Pourquoi ce pipeline est “pro” (dans un portfolio)

  • Traçabilité: le brut n’est jamais modifié (audit + reproductibilité).
  • Normalisation: mêmes colonnes, mêmes unités, mêmes types partout.
  • Robuste aux formats marocains/français: séparateurs (espaces fines), virgule décimale, “%”.
  • Qualité: checks rapides pour repérer incohérences (ex: 100%, pop).
  • Prêt pour l’IA: export JSON “dic complet” directement utilisable par le module Q&A et le générateur de rapports.

Note: si ton fichier RGPH a plusieurs feuilles ou des en-têtes non standard, change sheet_name et/ou utilise skiprows dans read_excel().
