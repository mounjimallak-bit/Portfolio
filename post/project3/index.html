Bien Immobilier

Plateforme Web de Location Immobilière

Flask Oracle SQL PL/SQL Tailwind

Application web complète de location immobilière développée avec Flask et Oracle permettant la gestion du cycle complet : Publication de biens • Recherche • Réservation • Confirmation • Paiement • Avis • Messagerie

Livrables : application Flask, scripts SQL/PLSQL, schéma BD, démo vidéo.
Rôles applicatifs : Visiteur / Standard / Locataire / Propriétaire / Admin (droits Oracle).

Stack & composants

  • Backend : Flask (routes, sessions, RBAC, gestion d’erreurs)
  • DB : Oracle (modèle relationnel, indexes, vues, rôles/grants)
  • PL/SQL : procédures/fonctions métier + triggers de sécurité et intégrité
  • UI : HTML/CSS/Tailwind + Jinja2

Fonctionnalités — Locataire

  • Consulter le catalogue via VUE_ANNONCES_PUBLIQUES / VUE_BIENS_PUBLICS
  • Rechercher par filtres via rechercherBiens(...)
  • Créer une réservation via creerReservation(...) (anti-chevauchement)
  • Consulter son historique via VUE_MES_RESERVATIONS / get_mes_reservations(...)
  • Payer via genererPaiement(...) puis validerPaiement(...) / echouerPaiement(...)
  • Consulter ses paiements via VUE_MES_PAIEMENTS
  • Messagerie (insertion contrôlée) via trigger trg_secu_message_identity

Fonctionnalités — Propriétaire

  • Gérer les biens avec sécurité via trg_secu_bien_owner
  • Créer/modifier/supprimer annonces via creerAnnonce, modifierAnnonce, supprimerAnnonce + trg_secu_annonce_owner
  • Gérer photos via trg_secu_photo_owner (protection propriétaire)
  • Gérer équipements via trg_secu_equipement_owner
  • Consulter réservations reçues via VUE_RESERVATIONS_POUR_MOI
  • Confirmer une réservation via confirmerReservation(...) (création automatique de LOCATION)
  • Suivre revenus via VUE_MES_REVENUS
  • Voir inventaire via VUE_MES_BIENS, annonces via VUE_MES_ANNONCES / get_mes_annonces(...)

Bugs / cas limites & corrections (noms réels PL/SQL)

Liste des problèmes rencontrés et mécanismes Oracle mis en place (procédures / fonctions / triggers / vues / rôles).

1) Chevauchement des réservations (anti-overbooking)

  • Cause : réservation sur une période déjà occupée
  • Détection : verifierDisponibilite(p_id_bien, p_debut, p_fin) (compte conflits)
  • Blocage : creerReservation(...) lève -20001 si conflit (transaction + rollback)
  • Recherche cohérente : rechercherBiens(...) exclut les conflits via NOT EXISTS

2) Usurpation d’identité du locataire à l’insertion

  • Cause : un utilisateur tente d’insérer une réservation pour un autre id_locataire
  • Correction : trigger trg_secu_resa_locataire force :NEW.id_locataire à l’utilisateur connecté

3) Accès non autorisé aux biens/annonces/photos/équipements

  • BIEN : trg_secu_bien_owner bloque UPDATE/DELETE si le bien ne correspond pas au propriétaire connecté
  • ANNONCE : trg_secu_annonce_owner vérifie le propriétaire du bien lié
  • PHOTO_BIEN : trg_secu_photo_owner empêche modification des photos d’un autre bien
  • BIEN_EQUIPEMENT : trg_secu_equipement_owner empêche modification des équipements d’un autre bien

4) Suppression d’un bien avec réservations actives

  • Cause : suppression d’un bien alors que RESERVATION est EN_ATTENTE / CONFIRMEE
  • Correction : trigger trg_no_delete_bien_with_active_res bloque DELETE (erreur -20010)

5) Fraude : modification d’un paiement “réussi”

  • Cause : UPDATE sur PAIEMENT après validation
  • Correction : trigger trg_no_update_paiement_if_reussi bloque toute modification si statut_paiement = 'REUSSI' (erreur -20011)
  • Workflow : validation via validerPaiement(p_id_paiement), échec via echouerPaiement(...), remboursement via emettreRemboursement(...)

6) Dates incohérentes lors de la confirmation

  • Règle : date_fin > date_debut (contrainte chk_dates_res)
  • Contrôle métier : trigger trg_reservation_check bloque confirmation si dates invalides (erreur -20015)
  • Automatisation : confirmerReservation(p_id_reservation) calcule le total via calculerPrixTotal(...) et crée la ligne LOCATION

7) Usurpation en messagerie

  • Cause : insertion avec un id_expediteur falsifié
  • Correction : trigger trg_secu_message_identity force :NEW.id_expediteur à l’utilisateur connecté

8) Note moyenne non mise à jour après avis

  • Correction : procédure majNoteMoyenne(p_id_location) (AUTONOMOUS_TRANSACTION) recalcule BIEN.note_moyenne
  • Automatisation : trigger trg_maj_note_bien (AFTER INSERT/UPDATE ON AVIS_BIEN)

Sécurité & droits Oracle

Rôles DB

  • ROLE_VISITEUR : lecture vues publiques (VUE_ANNONCES_PUBLIQUES, VUE_BIENS_PUBLICS)
  • ROLE_STANDARD : profil + messagerie
  • ROLE_LOCATAIRE : réservations, paiements, avis + vues personnelles
  • ROLE_PROPRIETAIRE : gestion biens/annonces/photos/équipements + vues propriétaires
  • ROLE_ADMIN : droits complets

pratiques appliquées

  • Contrôles critiques côté DB (triggers) + séparation des responsabilités (Flask vs Oracle)
  • Vues dédiées pour limiter l’exposition des données
  • Indexes pour accélérer recherche et jointures (réservations, paiements, messages)
