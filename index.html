Detecting faults from few labels: photovoltaic anomaly detection

Photovoltaic plants degrade quietly. Shading and other partial faults cut output for days or weeks before anyone notices, and labelled fault data is almost never available. This project learns normal operation from healthy data, detects staged shading faults, and then asks how much a handful of fault episodes can actually establish.

Approach

A semi-supervised ensemble: five dense and five LSTM autoencoders trained on healthy data only, their reconstruction errors ranked against a frozen reference and fused. Labels were used to select features, tune the models and set the alarm threshold (maximum F2 on validation), never to fit the networks. Evaluation follows a strictly chronological split.

What re-examination showed

After an external review, the result was tested further. A training-free nearest-neighbour distance performs comparably to the ten networks; the LSTM half adds nothing on test; the 3/3 episode result has a 95% interval of 0.29 to 1; and in the austral winter, absent from training, the detector raises 4 to 11 false alarms a week. A proof of concept for one fault signature, in one season, on one plant.

Deployment

The detector also runs as a streaming prototype. A replayer publishes five-minute measurements to Kafka, a Python consumer scores each point and writes to TimescaleDB, and a provisioned Grafana dashboard renders the result live, with the same scores as offline. The whole stack starts from a single docker compose up.

Results

PR-AUC (test)0.78
Test episodes3 / 3
kNN baseline (test)0.88
Winter false alarms4–11 / week

Test partition opened once, after every design choice was fixed; base rate 0.026. The 3 test episodes repeat one staged experiment, so the uncertainty is large (test PR-AUC 0.48 to 0.94). Dataset: public Zenodo record of a 4 kW PV installation in La Réunion, with labelled shading faults, provided by the project supervisor.

Did poverty fall evenly across Souss-Massa? A validated dataset of official statistics

Morocco's statistics institute (HCP) publishes regional figures mainly as PDF yearbooks, which makes comparisons across years and territories slow and error-prone. I transcribed 48 HCP tables for the Souss-Massa region, checked them automatically, and used them to ask whether poverty declined uniformly across the region's communes between 2004 and 2014.

Data validation

A validator reads the tables without running the application and checks that totals equal the sum of their parts, that every copy of a table matches its source, and that each commune on a map reaches exactly one polygon of the official boundaries, inside its own province. To show the checks work, a test suite seeds six typical transcription errors into a copy of the data and confirms that each one is reported.

Analysis

Poverty is described at two levels: the 179 communes and urban centres with a published rate in 2004, 2007 and 2014, each counted once, and the population-weighted rate that the HCP publishes for each province. The two levels answer different questions and rank the territories differently. The analysis is descriptive: it does not identify causes.

Application

The data can be explored in a Streamlit application with provincial and commune choropleth maps, a PDF report generator and a question-answering assistant built on the Gemini API.

Results

The 179 units are every unit with a published rate, not a sample, so no significance test is reported. The 2004, 2007 and 2014 rates come from three separate HCP poverty maps whose comparability over time has not been established. Tata's figure is its population-weighted rate; the other five territories fell by 57% to 77%.
